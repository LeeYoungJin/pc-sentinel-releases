PC Sentinel 사용 안내서

개발 PC 에 깔린 Node.js·Python·Java·.NET 의 버전과 보안 패치, AI 도구 스킬, PATH 를 한 화면에서 점검하고 필요한 것만 안전하게 고치는 Windows 앱입니다.

Windows 10 · 11점검은 조회만바꾸기 전 항상 확인사용자 정보는 가려서 표시

무엇을 하는 앱인가요

앱을 열면 아래 영역을 차례로 점검하고, 손볼 것이 있으면 무엇을 왜 해야 하는지 알려 줍니다.

영역알려 주는 것할 수 있는 일
Node.js · Python · Java · .NET설치된 버전, 같은 라인의 최신 버전, 보안 패치 여부, 지원 종료(EOL) 날짜보안 패치 업데이트, 중복·지원 종료 버전 정리, Python 버전 이전
AI 스킬Claude Code·Codex 의 스킬·훅·MCP 서버가 어떤 런타임에 기대는지, 깨진 경로깨진 경로 복구 (설정 파일 백업 후)
관계도런타임 ↔ 사용하는 도구·프로그램·프로젝트의 연결지우면 영향받는 곳 미리 확인
AI 사용량Claude Code·Codex 의 5시간·주간 한도와 토큰 사용량남은 한도와 초기화 시각 확인
PATH · 정리없는 경로·중복 PATH, 지워도 되는 임시 파일·캐시PATH 정리(백업·복원), 파일 정리
보안 점검자동 실행 항목, 설정 변조, 위장 프로세스, 브라우저 확장·바로가기, AI 도구 오남용 설정항목별 확인·조치 방법 보기, 정상 항목은 예외로 등록 (조회 전용)
점검은 아무것도 바꾸지 않습니다설치·삭제·설정 변경은 계획을 보여 주고, 마지막에 Windows 확인 창에서 '실행'을 눌러야만 진행됩니다.

설치와 업데이트

  1. 릴리스 페이지 github.com/LeeYoungJin/pc-sentinel-releases 에서 최신 버전의 PC Sentinel_x.y.z_x64-setup.exe 를 내려받습니다.
  2. 설치 파일을 실행합니다. 이 PC 의 모든 사용자용으로 Program Files 에 설치되므로 관리자 권한 확인(UAC) 창이 한 번 뜹니다.
  3. 시작 메뉴에서 PC Sentinel 을 엽니다. 처음 열면 모든 영역을 자동으로 점검합니다.

새 버전이 나오면

앱이 시작할 때 새 버전을 확인하고 안내 창을 띄웁니다. '지금 업데이트'를 누르면 내려받아 설치한 뒤 앱이 다시 시작됩니다. 아래 상태 표시줄의 새 버전 설치 버튼으로도 할 수 있습니다.

보안 프로그램 때문에 업데이트가 막힌다면일부 보안 프로그램은 시스템 임시 폴더(%TEMP%)에 내려받은 설치 파일을 막습니다. 그래서 앱은 회사가 지정한 업데이트 폴더에 내려받습니다. 폴더 위치는 사내 안내를 따르고, 업데이트 안내 창이나 설정에서 확인할 수 있습니다.

화면 구성

왼쪽 메뉴에서 영역을 고르고, 위쪽 앱 바에서 다시 점검하고, 아래 상태 표시줄에서 진행 상황을 봅니다.

  1. 1
    왼쪽 메뉴 · 런타임 / 도구 / 시스템으로 묶여 있습니다. 숫자 배지는 손볼 항목 수, 도는 표시는 작업 중이라는 뜻입니다.
  2. 2
    앱 바 · 이 화면 다시 점검(지금 보는 영역만), 모두 다시 점검, 도움말(?), 더보기(⋯: 변경 내역·업데이트 확인·설정·버전 정보).
  3. 3
    영역별 카드 · 상태와 한 줄 요약을 보여 줍니다. 누르면 그 화면으로 이동합니다.
  4. 4
    상태 표시줄 · 점검 중인 영역, 마지막 점검 시각, AI 사용 한도 막대, 앱 버전. 한도 막대를 누르면 AI 사용량 화면으로 갑니다.

점검 결과 읽는 법

개요 카드와 메뉴의 배지는 다음 뜻입니다.

표시뜻할 일
정상손볼 것이 없습니다.없음
해당 사항 없음이 PC 에 그 런타임이 설치되어 있지 않습니다. 점검할 것이 없으니 정상입니다.없음
손볼 항목 1보안 패치·지원 종료·깨진 경로 등 고칠 것이 있습니다.카드를 눌러 '다음에 할 일'을 따라 합니다.
점검 중지금 조회하고 있습니다. 두 영역씩 차례로 점검합니다.잠시 기다립니다.

런타임 표의 상태 칸은 최신 보안 패치 지원 종료 등으로 각 버전의 상황을 알려 줍니다. 네트워크가 막혀 최신 정보를 못 받으면 마지막으로 저장한 정보를 쓰고 노란 안내를 띄웁니다.

런타임 업데이트

보안 패치가 필요한 버전이 있으면 화면 위쪽 다음에 할 일에 무엇을 할지 나옵니다. 아래는 Java 21 에 보안 패치가 나온 경우입니다.

  1. 표에서 업데이트할 라인의 체크 칸을 고르고 선택 라인 업데이트를 누릅니다. (전부 하려면 '전체 업데이트 계획')
  2. 계획 확인 창이 뜹니다. 무엇을 설치·삭제하는지, 제외된 항목은 왜 제외됐는지 보여 줍니다. 아직 아무것도 바뀌지 않았습니다.
  3. 내용이 맞으면 실행을 누릅니다. 마지막으로 앱이 띄우는 Windows 확인 창에서 '실행'을 눌러야 시작됩니다.
  4. 진행 상황은 화면 아래 작업 로그에 남고, 끝나면 새 버전이 실제로 동작하는지 검증한 뒤 다시 점검합니다.

Node.js

nvm-windows 로 설치한 버전을 관리합니다. 업데이트 후 같은 라인의 구버전 삭제, 중복·지원 종료·고아 폴더 정리를 할 수 있습니다. 실행 중인 Node 버전은 삭제하지 않고 보류합니다.

Python · Java

winget 을 먼저 쓰고, winget 에 새 버전이 없으면 python.org·Adoptium 공식 설치 파일을 받아 디지털 서명을 확인한 뒤 설치합니다. Python 은 오래된 버전에서 새 버전으로 옮기는 버전 이전도 있습니다.

.NET 은 Visual Studio 등이 함께 설치한 버전이 많아, 설치 주체를 보여 주고 직접 지워도 안전한 것만 정리 대상으로 고릅니다.

AI 스킬

Claude Code·Codex 에 설치한 스킬·훅·MCP 서버가 어느 런타임 버전에 기대는지 보여 줍니다. Node 버전을 지우면 멈추는 항목은 버전 고정, 이미 경로가 끊긴 항목은 깨짐으로 표시됩니다.

깨진 항목은 경로 복구로 현재 설치된 Node 위치에 다시 연결할 수 있습니다. 설정 파일은 고치기 전에 백업합니다. 인증 정보 파일과 MCP 환경 변수는 읽지 않습니다.

런타임과 그것을 쓰는 AI 도구·실행 중인 프로그램·프로젝트를 선으로 이어 보여 줍니다. 어떤 버전을 지우기 전에 영향받는 곳을 확인할 때 씁니다.

AI 사용량

Claude Code 와 Codex 를 얼마나 썼는지, 사용 한도가 얼마나 남았는지 봅니다.

기본 (아무것도 켜지 않음)이 PC 의 사용 기록 파일에서 토큰 수만 모아 보여 줍니다. Codex 는 기록에 남은 한도도 보입니다. 질문·코드 내용은 읽어 두지 않습니다.
인증으로 자세히 보기도구별로 켜면 이 PC 의 로그인 정보로 5시간·주간 한도와 초기화까지 남은 시간을 조회합니다. 켤 때 Windows 확인 창에서 동의해야 하며, 언제든 끌 수 있습니다.

막대 색은 80% 이상 노랑, 90% 이상 빨강입니다. 같은 한도 막대가 아래 상태 표시줄에도 항상 보입니다.

PATH · 정리

PATH 정리는 존재하지 않는 경로와 중복(앞선 항목은 유지)만 지우고, 바꾸기 전 PATH 를 백업해 언제든 복원할 수 있습니다. 시스템 PATH 를 고칠 때는 관리자 권한 창이 뜹니다.

정리는 7일 지난 임시 파일, 크래시 덤프 같은 것을 지웁니다. npm·Yarn·pip 캐시는 지우면 다음 설치 때 다시 내려받아야 하므로 '재다운로드 필요'로 표시되고 직접 골라야 합니다. 휴지통·브라우저 데이터·Windows 폴더는 대상이 아닙니다.

보안 점검

악성코드나 원치 않는 프로그램이 흔히 숨는 곳과, 보안을 약하게 만드는 설정을 살펴봅니다. 조회만 하며 아무것도 지우거나 종료하지 않습니다. 고칠지는 사용자가 안내를 보고 직접 정합니다.

분류살펴보는 곳
자동 실행로그인·시작 때 실행되는 레지스트리 Run, 시작프로그램 폴더, 예약 작업, 서비스, 실행 가로채기(IFEO), Winlogon·AppInit, WMI 구독
설정 변조hosts 파일, 프록시·PAC, DNS, 사용자가 추가한 루트 인증서, Windows 방화벽, 사용자 계정 컨트롤(UAC), 보안 정책
프로세스시스템 프로세스를 흉내 낸 이름, 정상 위치가 아닌 곳의 시스템 프로세스, 임시·다운로드 폴더의 서명 없는 프로그램, 의심스러운 명령
브라우저Chrome·Edge·Whale 확장, 정책으로 강제 설치된 확장, 주소가 붙은 브라우저 바로가기
AI 도구Claude Code·Codex 의 권한 확인 생략 설정, 외부 MCP 서버, 버전을 고정하지 않은 MCP, 네트워크에 열린 로컬 LLM 서버

주의정상일 수도 있지만 확인이 필요한 설정·항목입니다.확인·조치 방법을 따라 직접 확인합니다.

확인·조치 방법

각 줄 오른쪽의 확인·조치 방법을 누르면 그 항목이 정확히 어디에 있는지와, 직접 찾아가 확인하는 방법, 고치는 방법이 Windows 11 화면 기준으로 나옵니다.

  • 루트 인증서는 certmgr.msc 에서 지문(Thumbprint)으로 찾는 방법을, hosts·프록시는 어느 파일·설정 화면을 열지 알려 줍니다.
  • MCP 서버는 등록된 범위(프로젝트별·사용자 전체·Codex)에 맞는 지우는 명령을 그대로 붙여 넣을 수 있게 보여 줍니다. 계속 쓸 경우 버전을 고정해 다시 추가하는 방법도 함께 나옵니다.
  • Winlogon·AppInit·WMI·위장 프로세스처럼 악성코드가 흔히 쓰는 위치는 직접 고치지 말고 보안 담당 부서에 먼저 알리라는 안내가 붙습니다.

예외로 등록 · 해제

회사가 배포한 프로그램처럼 정상으로 확인한 항목은 예외로 등록을 누르면 이 PC 에서 다시 표시하지 않고 손볼 항목 수에서도 빠집니다. 예외는 이 PC 에만 저장됩니다.

보안 점검은 백신을 대신하지 않습니다일반 사용자 권한으로 점검하므로 일부 시스템 영역은 확인하지 못할 수 있습니다. 악성코드 검사·치료는 회사 백신 프로그램을 사용하고, 위험 항목이 이해되지 않으면 보안 담당 부서에 문의하세요.

설정

오른쪽 위 ⋯ → 설정에서 업데이트 파일을 내려받을 폴더를 확인하고 바꿀 수 있습니다.

상황업데이트 파일 위치
직접 고른 폴더가 있음그 폴더
고른 폴더 없음회사 기본 폴더 (상위 폴더가 있으면 앱이 자동으로 만듦)
회사 기본 폴더를 쓸 수 없음시스템 임시 폴더 — 업데이트 안내 창에서 '폴더 만들기'를 권합니다

네트워크·이동식 드라이브, Windows·Program Files 폴더, 쓰기 권한이 없는 폴더는 고를 수 없습니다. 업데이트할 때는 그 폴더 안에 현재 사용자와 관리자만 접근할 수 있는 작업 폴더를 만들어 내려받습니다.

안전 장치

  • 두 번 확인 · 화면의 계획 확인 + 앱이 직접 띄우는 Windows 확인 창. 화면만으로는 실행되지 않습니다.
  • 실행 직전 다시 확인 · 계획을 본 뒤 PC 상태가 바뀌었으면 다시 계획합니다.
